Optional hook executed once per plugin by dbtool and dbtool-gui after a successful migrate, migrate-to-release or apply, including runs where nothing was pending. It runs on the migration connection while the migration lock is still held (unless the caller opted out of locking, as with dbtool --no-lock), and never for dry runs, read-only commands or a failed migration. Plugins use it for work that needs the migrated schema, such as seeding reference data.

A hook body that throws makes the command fail; the migrations it ran after stay applied. The macro exports a non-throwing C entry point that catches the exception and hands its message to the host, so no exception crosses the shared-library boundary.

Use as:

LIGHTWEIGHT_MIGRATION_PLUGIN_POSTMIGRATE(connection, manager)
{
MyPlugin::SeedReferenceData(connection);
}

Work a plugin runs before the first pending migration of migrate, apply and migrate-to-release.

The first parameter is the migration connection, on which the host holds the migration lock unless it opted out of locking; then the host's manager, the step's own task and the execution mode, in which a dry run makes the step report its plan and change nothing.

◆ BackupRecordCovers()

LIGHTWEIGHT_API bool Lightweight::SqlMigration::BackupRecordCovers ( BackupRecord const &  record,
MigrationHistoryState const &  state 
)
noexcept

Whether record covers the database state state.

Only a backup or restore record can cover, and it does when it saw exactly the current migration history: its observedState.digest equals the state's. Any migration applied, re-applied, rolled back or re-stamped since changes the digest. Only values read from the database are compared, so createdAt and the clocks of the hosts involved play no part. Any other kind covers nothing.

Parameters
recordThe record to test.
stateThe current migration state.
